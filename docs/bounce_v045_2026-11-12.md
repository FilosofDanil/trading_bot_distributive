# density-bounce v0.4.5: исправления по критике и прогон на истории месяца (2026-11-12)

## Итог

- v0.4.5 убирает два доказанных механизма убытка: молодые плотности (спуфинг) и плотности, слишком маленькие для
  потока, который в них идёт. Вход теперь ставится только после того, как плотность выдержала касание 15 секунд.
- Положительного ожидания на истории нет ни в одной выборке. Сама сделка без плотности стоит −0.10R, фильтры
  подтягивают результат к нулю, но не выше. Это более чистый эксперимент, а не рабочая стратегия.
- Версия работает в paper. В live её переводить нельзя, пока журнал планов не покажет плюс на ≥ 200 сделках.

## Что было не так и что сделано

| Замечание из критики | Что сделано в v0.4.5 |
|---|---|
| 1. Лимитка перед стеной исполняется, когда стену уже атакуют | Вход с подтверждением (`confirm_secs = 15`): заявка сначала «взводится», ставится через 15 с после того, как цена дошла до уровня входа, и только если плотность ≥ 70 % пика и её не проедают. Иначе отмена `unconfirmed` |
| 2. После входа плотность не участвует в сделке | Критерий реальности (ниже): в сделку попадают только плотности, способные задержать цену на минуту. Выход по исчезновению стены не возвращён |
| 3. Фильтр контртренда ничего не отсекал | Тренд 1h берётся ДО начала хода, а не на входе. `accel` = скорость подхода / средняя скорость самого хода; значение 99 убрано |
| 3. `stop_depth_k` не срабатывал | Проверка оставлена (она сработает на большой позиции); пропуск по ней пишется в журнал планов. Порог не менялся: на истории проверить нечем |
| 4. Плотность не сверялась с текущим потоком | **Критерий реальности** `hold_min = 60`: размер плотности / односторонний агрессивный поток в её сторону (быстрее из последней минуты и трёх минут) ≥ 60 с. Рабочая заявка снимается при < 30 с (`density_weak`) |
| 5. Возраст 20 с считался от попадания в окно 1.5 % | Плотности отслеживаются с 3 % от цены, минимальный возраст 60 с |
| 6. Серия входов в общем проливе | Фильтр рынка `mkt_max = 1 %`: нет входа, если медиана изменения остальных монет в наблюдении за 30 мин ≥ 1 % в сторону плотности |
| 7. Малые выборки, нет контрфакта | Журнал планов: каждый план (исполненный, отменённый, пропущенный фильтром) пишется с причиной и с тем, что сделал бы простой вход: `<state>_plans.jsonl`, `GET …/plans` |
| ATR не посчитался → стоп 0.15 % | Нет ATR — нет сделки |
| Причины отмен терялись | Каждая отмена: строка `CANCEL` в логе, счётчик `cancel_<причина>`, запись в журнале планов |
| Повторный вход в ту же стену через минуту | После отмены из-за самой плотности она закрыта на 30 мин (`wall_cool`); после прочих отмен монета отдыхает 60 с |
| В журнале нет версии правил | У каждой сделки и плана поле `ver`, у сделки ещё `pid` плана |
| Paper завышал защиту отменой | Симулятор: заявка доходит и снимается с задержкой `SIM_LAG = 0.3` с, за это время она может исполниться |
| Лимиты слабые в R | Дневной стоп `DAY_LOSS_R = 6`; в live после 30 сделок версии среднее < −0.3R останавливает стратегию |

Не сделано: live-брокер по-прежнему опрашивает REST (0.4 с), а не слушает пользовательский поток. Это правка
с реальными деньгами, её нельзя проверить без ключей; в paper задержку теперь моделирует `SIM_LAG`.

## Прогон на истории: метод

Binance не хранит историю стакана, поэтому «прогнать бота на месяце» буквально нельзя. Месяц разложен на три части
(скрипты и данные: `Engine/Strategy_tester/research/bounce_v045`):

- **A. Сделка без стены.** Минутные свечи 69 монет за 2026-10-12 → 11-12. Каждая минута, где выполнены ценовые
  правила (ход ≥ 2.5 % за 30 мин, подход ≥ 0.8 % за 3 мин, цена ещё идёт), получает условную стену в 0.2 % дальше
  по ходу; вход, стоп 2×ATR, половина на +1R, тейк 50 % хода — как у бота. Это то, что бот делает после входа.
- **B. Реальные плотности.** 4618 планов лаборатории за 24–31.10 (54 монеты, 997 входов, причина каждой отмены),
  26 планов v0.4.0 из paper и 73 live-сделки. Поток в сторону плотности взят из минуток (taker sell / buy).
  Входы лаборатории переиграны с выходами v0.4.5.
- **C. Результат самой лаборатории** на тех же входах: он считан по тикам (стоп 0.12 %, тейк 2R).

R — результат к риску, комиссии полные (2 bp мейкер, 5 bp тейкер + 2 bp проскальзывания стопа). Интервал 95 %,
бутстрап по монето-дням. Вход считается исполненным, только если свеча прошла сквозь цену; свеча входа считается
только против позиции; свеча со стопом и тейком — стоп.

## Результаты

| Выборка | Сделок | Средний R | 95 % интервал |
|---|---|---|---|
| A. Без стены, весь месяц | 3835 | **−0.10** | −0.13 … −0.06 |
| A. Первая / вторая половина месяца | 1917 / 1918 | −0.10 / −0.10 | |
| B. Реальные плотности, выходы v0.4.5: плотность < 60 с потока | 501 | −0.17 | −0.29 … −0.06 |
| B. Плотность ≥ 60 с потока (критерий реальности) | 139 | −0.14 | −0.35 … +0.07 |
| B. Плотность и сделка живы через 15 с после входа (приближение входа с подтверждением) | 149 | −0.00 | −0.19 … +0.18 |
| B. То же и ≥ 60 с потока, возраст ≥ 60 с | 50 | +0.03 | −0.32 … +0.36 |
| B. Все фильтры v0.4.5 вместе, без подтверждения | 7 | −0.13 | −0.76 … +0.77 |
| B. Live, фактический результат: < 60 с / ≥ 60 с потока | 44 / 29 | −0.99 / −0.47 | |
| C. Лаборатория по тикам: < 60 с / ≥ 60 с потока | 730 / 267 | −0.66 / −0.51 | |
| C. Лаборатория по тикам: резкий подход (правила v0.4.5) | 64 | −0.01 | −0.44 … +0.34 |

Что из этого следует:

1. **Возраст — рабочая защита от спуфинга.** Плотность моложе 60 с пропадала до входа в 91 % планов
   (60–300 с: 42 %, старше: 21 %).
2. **Критерий реальности отделяет живые стены.** После входа плотность пропадала в 68 % случаев при < 60 с потока
   и в 41 % при ≥ 60 с. Результат лучше во всех трёх выборках, но остаётся ниже нуля.
3. **Подтверждение 15 с бьёт в главную причину.** 89 % плотностей, пропавших после входа, пропали за 15 с,
   половина — за 1.3 с. Входы, где плотность и сделка пережили 15 с, дают около 0R против −0.22R у остальных.
4. **Преимущества нет.** Ни одна выборка не выше нуля с уверенностью, а сделка без стены стоит −0.10R.
   Тренд, ускорение и движение рынка на 3835 сделках меняют результат на сотые R.
5. **Сделок будет мало.** Все фильтры вместе оставили 7 входов из 997 за неделю лаборатории. Из 26 планов v0.4.0
   критерий и возраст пропускают 12; из 9 исполненных — 4 (три стопа и один ноль), ещё до подтверждения.

## Чего прогон не показывает

- Цену входа с подтверждением и окно отслеживания 3 % проверить на истории нельзя: нужен стакан.
- Приближение подтверждения смотрит на 15 с вперёд от входа лаборатории и считает результат от её цены.
- Пороги 60 с, 15 с и 1 % выбраны по смыслу, а не подбором; выборки с ними малы (7–149 сделок).
- Paper-исполнение лаборатории не учитывает очередь и задержку; live был хуже paper на каждом шаге.

## Дальше

1. Paper v0.4.5 до ≥ 200 записей в журнале планов; разбор по `skip`, `act` и `shadow.r`.
2. Правило остановки: если после 30 сделок средний R < −0.3 или после 100 планов теневой результат прошедших
   фильтры не лучше пропущенных — стратегию закрывать, а не настраивать дальше.
3. Live не включать, пока нижняя граница интервала на paper не выше нуля.
