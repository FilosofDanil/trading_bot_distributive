# Go port of the Python runners (round 5, 2026-11-14)

The Python runners `funding_carry` (carry/) and `density_bounce` (bounce/) are rewritten in Go. The strategy,
the HTTP contract and the state files do not change. Memory is cut by design (see `CLAUDE.md`).

## Shared conventions (both runners)

| Topic | Rule |
|---|---|
| Module | each folder is its own module: `funding_carry/go.mod` → `module fundingcarry`, `density_bounce/go.mod` → `module densitybounce`; `go 1.24.3` (as `control`) |
| Deps | stdlib only; bounce adds `github.com/gorilla/websocket v1.5.3` (the version `control` uses) |
| Layout | `main.go` (subcommands as the Python `__main__`), `internal/<pkg>/` one package per Python module |
| HTTP | `docs/runner_api.md`, byte-for-byte the same routes, codes and error texts as `api.py`; listen on `:PORT` (Go listens dual-stack, IPv6 for the Railway private network); `/healthz` open; `/v1/*` needs `X-Control-Token` (constant-time compare), 503 without `CONTROL_TOKEN` |
| JSON | the same field names as the Python dicts. Empty lists are `[]` (never `null`); Python `None` is `null`. NaN / ±Inf never reach `json.Marshal` (it fails): clamp or turn them into `null` |
| State file | the same JSON layout the Python runner writes. **The Go runner must load the file the Python runner left on `/data`** (live carry may hold real pairs). The loader accepts Python's `NaN` / `Infinity` / `-Infinity` tokens (as null). An unreadable state file is never overwritten: exit with an error. Write atomically: tmp file + rename |
| Times | ISO `2006-01-02T15:04:05Z` UTC, days `2006-01-02`, epoch ms as int64 |
| Logs | stdout, the same lines as the Python `print` (`[level] msg` for events) |
| Concurrency | goroutines for the HTTP server, the loop, the watchdog; `sync.Mutex` for the store (Python `RLock` → split into locked / unlocked helpers); `TryLock` where Python used `acquire(blocking=False)` |
| Shutdown | SIGTERM / SIGINT: stop the server, wait for a running cycle up to 25 s, save the state |
| Docker | as `control/Dockerfile`: `golang:1.24-alpine` builds with `CGO_ENABLED=0 go test ./... && go build -trimpath -ldflags="-s -w"`, then `gcr.io/distroless/static-debian12`; the same `ENV` defaults as the Python image (`STATE_FILE`, `PORT`, `MODE`), plus `GOMEMLIMIT` |
| Tests | every pytest case is ported to `go test` with the same intent; pure functions are also checked against fixtures generated by running the **Python** code (`testdata/*.json`), so the port is proven equal, not assumed |
| Version | carry `0.2.0`, bounce `0.5.0` (the strategy is unchanged, the runtime is new) |

## Types: what is narrowed and why

7 significant digits (float32) are enough for market data that is only compared or summed into a decision,
not for money that is booked. Every narrowing below has a test.

| Data | Type | Check |
|---|---|---|
| order-book price | `int32` tick (price / tickSize), clamped at ±2^29 | `book_py_test.go` |
| book level qty, tape qty | `float32` | `book_py_test.go`: densities, flows equal to Python |
| turnover buckets | `float32` USDT per second, summed in `float64` | relative error < 1e-6 against Python |
| mids, 1m bars, 1h closes | `int32` ticks (mid as bid + ask), `int32` minute / hour index | exact: ATR / trend / history equal to Python |
| tape / mid timestamps | `int64` ms (Binance event time, exact) | — |
| density counters (eaten) | `float64` per density, not per price | `book_py_test.go` |
| carry hourly klines (universe build) | `float32` OHLC + quote volume, transient per symbol | screens give the same tags as the Python on the fixture |
| state, positions, PnL, order sizes | `float64` | unchanged |

## funding_carry: what changes besides the language

- **No pandas.** `funding_8h`, the screens and `decide` are plain loops; they reproduce the pandas semantics
  (rolling median with `min_periods=1` + `bfill` + `clip` + `fillna`, `nlargest` / `nsmallest` with
  `keep="first"`, Pearson `corr` on the inner join, NaN skipping in `mean` / `max`).
- **The universe build streams.** Python held an hourly panel of every perp (~525 × 1 500 bars) at once.
  Go fetches BTC first, then one symbol at a time (4 workers), reduces its bars to the per-day screen features
  and drops the bars. Only the features (a few numbers per symbol and day) are kept until the day is ranked.

## density_bounce: what changes besides the language

- **No 50 000-trade tape per symbol.** The tape keeps only the prints of the last `TapeKeep` seconds
  (`max(approach_secs, impulse_secs, 300) + 10` = 310 s by default), 16 bytes each (int64 ms, int32 tick, float32 qty
  with the aggressor side in its sign). That covers `flow()` (180 s) exactly and the 300 s a shadow plan may wait
  for an unsynced book. Python kept 50 000 objects of ~200 bytes per symbol.
- **Turnover in 1-second buckets.** `turnover()` / `minute_turnover()` read 1 024 buckets (int64 s + float32 USDT)
  instead of a `(ts, usd)` tuple per print over 15 min. Exact when prints fall on whole seconds; otherwise at most the
  part of one second at the window's start is left out (`TestTurnoverBucketsBound`).
- **No `cum_at`.** It grew forever (every traded price). A density now counts the aggressive qty at its own
  price from the moment it is first seen, which is what `cum(tick) - base` computed.
- **`traded()` is gone**: it had no caller.
- **`ShadowSeen` and `Failed` are pruned** every `ShadowEvery` (600 s) of their entries that no longer change a
  decision (a shadow seen ≥ 600 s ago passes like an unseen one, an expired block blocks nothing). Python kept them
  forever: one entry per (symbol, density, gate). `TestPruneDropsOnlyDeadEntries`; the Python replay still matches.
- **Best quotes are cached** (Python scanned the whole level dict on every `best_bid()`); mids, 1m bars and 1h closes
  are int32 ticks (mid = (bid + ask) / 2, exact).
- **The closed-trade journal leaves the state file** for `<state>_trades.jsonl` (the state was rewritten whole,
  1 000 trades with their features, on every event). RAM keeps the last 50 records and the (version, R) pairs the live
  guard needs. The plan journal is read from its tail, not loaded whole (it rotates at 20 MB).
- Proof: `internal/book/book_py_test.go` replays a 20-minute synthetic stream (snapshot, 12 000 diff events with a gap
  and a resync, 3 600 prints, density scans every 0.5 s) recorded through the Python `book.py`; all 80 checkpoints
  (quotes, flows, turnover, ATR, history, trend, the whole density table) are equal.

## Results (2026-11-14, before deploy)

| | funding_carry | density_bounce |
|---|---|---|
| equal to Python | funding_8h 90 series, decide 320 + 18 fetched markets, screens, paper 3 scenarios (1e-9); `once --preview` for 2026-11-13 identical | book 80 checkpoints; scan on 300 books (every feature); 2 h paper replay, 6 symbols, 34k events: trades, plan journal, stats, event texts equal |
| state files | Python `carry_state.json` loads and round-trips | Python `bounce_state.json` loads; trades move to `_trades.jsonl` once |
| peak working set | 237 MB → 29 MB (daily cycle) | 145.5 MB → 46.5 MB (10 min paper, 16 symbols) |
| image | 15.9 MB | 16.3 MB |
| control e2e | PASS | PASS |
| not tested | real signed Binance calls (httptest only) | live mode on a real account (fake exchange only); Linux RSS |

Known numeric differences in bounce (float32 / 1 s buckets, all within the tests): an exact threshold tie can flip;
`minute_usd` with fractional-second prints is off by ≤ 1 s of the span (seen 0.02 %); `stop_atr` can differ by one
rounding unit on a tie. Report lines with equal counts sort by name.
